Share of Traffic on OpenRouter

What models developers actually run — measured, not estimated.

This is one gateway, not the market. These figures describe traffic routed through OpenRouter. Most enterprise inference goes directly to Anthropic, OpenAI or Google Cloud and never appears here. OpenRouter states this themselves: the rankings "describe traffic routed through OpenRouter, not the whole market and not usage on a model provider's own API." It is also public traffic only: private models, private endpoints and zero-data-retention requests are excluded from OpenRouter's datasets at the source.
Tokens from different vendors are not directly comparable. Each provider counts with its own tokenizer, so a token in one row is not the same unit as a token in another. Summing across vendors adds unlike quantities — which is what every "AI market share by tokens" figure silently does. Request share, in the first tab, is the more comparable measure.

Volume versus value

Each dot is a vendor. Horizontal axis is share of tokens routed; vertical axis is share of estimated spend. The diagonal is parity — a vendor sitting on it earns exactly in proportion to the volume it moves. Above the line, a vendor captures more value than volume. Below it, the reverse. Dot size is absolute token volume.

x = vendor tokens ÷ (attributed + other)  ·  y = vendor est. USD ÷ total est. USD  ·  ratio = y ÷ x  ·  dot area ∝ absolute tokens

Ranking churn, not only demand. These lines are share of the daily top-50 attributed traffic. Everything outside the daily top 50 arrives as one "other" row whose vendor mix is not published, so when a vendor's model drops out of the top 50 its line falls for reasons unrelated to demand. Traffic by task

OpenRouter classifies traffic by task — what the request was doing — not by industry. Both measures are shown throughout, because they can disagree sharply.

request share and token share are published directly by /api/v1/classifications/task as fractions of classified traffic  ·  ×100 only, no further arithmetic

Estimated routed spend derived figure

This is not enterprise spend. No public API publishes enterprise API spend. This figure is computed here by multiplying token volume by each model's published list price. It covers gateway-routed traffic only and uses list rates, which negotiated enterprise contracts sit below.
per model = tokens × (prompt price + completion price) ÷ 2  ·  joined on canonical_slug  ·  price coverage not reported by this build  ·  list prices from one registry snapshot (promotions included, caching not modelled), not negotiated rates

Open-weight versus proprietary

Measured on share of routed token traffic, not on how many models exist — one high-volume open model outweighs many rarely-used ones. Window: — fixed, because licence class is per model and the weekly series is stored per vendor.

share = Σ tokens of models in that licence class ÷ (attributed + other)  ·  measured on token traffic, not model count
